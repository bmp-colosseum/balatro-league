# SEO

What's indexed, what's noindex (and why), and where to change either one. Written
from the Tier-1 technical leaves in
[.claude/knowledge/seo/01-audit-and-plan.md](../../.claude/knowledge/seo/01-audit-and-plan.md),
which has the full audit this page summarizes.

Sources: [web/lib/seo.ts](../../web/lib/seo.ts),
[web/app/robots.ts](../../web/app/robots.ts),
[web/app/sitemap.ts](../../web/app/sitemap.ts),
[web/lib/json-ld.ts](../../web/lib/json-ld.ts).

## Indexable (public, in the sitemap)

`/standings`, `/seasons`, every `/seasons/[id]`, every `/divisions/[id]`,
`/hall-of-fame`, `/how-it-works`, `/join`, `/stats`, `/traits`. Each gets a real
title, description, canonical link, and Open Graph/Twitter card through the shared
`pageMetadata()` helper in `web/lib/seo.ts`, so a link pasted into Discord unfurls
properly instead of showing the generic site title.

**Player profiles (`/profile/[id]`) are indexed as of 2026-10-13**, decided by the
TO -- exposing Discord display names and avatars to search was an open question in
the original audit; it's resolved now. `generateMetadata` there calls
`pageMetadata()` with no `noIndex` flag, same as every other public page. Only
profiles with at least one CONFIRMED (played) match are listed in `app/sitemap.ts`
-- a profile with zero history isn't worth a crawl-budget entry with nothing on
it, though it's still reachable and still indexable if linked to from elsewhere
(standings, a division page, a shared link).

## Noindex (crawlable, but told not to rank)

Nothing currently uses this -- the `noIndex` flag on `pageMetadata()` (`web/lib/
seo.ts`) stays available for the next page that needs "crawlable but not ranked"
(sets `<meta name="robots" content="noindex">` while still keeping a title/
description/canonical, so the page still unfurls properly in Discord). Player
profiles were the one caller until the indexing decision above retired it.

## Blocked entirely (`web/app/robots.ts`)

`/admin`, `/me`, `/auth`, `/report`, `/changes`, `/api` are disallowed in
`robots.txt`. These are either organiser tools or signed-in-only action pages with
no public content.

`/profile` is **not** in this list -- it's ordinary public content now. The
general principle still matters for the next noindex-but-crawlable page though: a
`noindex` meta tag only works if the crawler is allowed to fetch the page and see
it. Blocking it in `robots.txt` as well would hide that very instruction and risk
the bare URL getting indexed anyway from an external link, with no title or
description. Block real private sections in `robots.ts`; use the per-page
`noIndex` flag for "crawlable but not indexed" ones.

## Excluded from the sitemap, but not noindex

**`/players`** redirects signed-out visitors (including Googlebot) straight to
`/auth/signin`, so a sitemap entry would just point crawlers at a redirect with
nothing to index. It keeps ordinary indexable metadata (nothing stops a signed-in
user from seeing a sensible tab title) but isn't listed in `app/sitemap.ts`.

**`/changes`** 404s for non-admins (`hasTier("ADMIN")` gate in the page itself), so
it was left with no metadata export at all -- same as before this leaf, and for the
same reason documented in that file: a title would otherwise leak onto the 404.

## Admin pages

`web/app/admin/layout.tsx` sets `robots: { index: false }` once, covering every
page under `/admin/**` -- new admin pages inherit it automatically and don't need
their own `robots` field.

## JSON-LD

`web/lib/json-ld.ts` is a pure builder module (no React/Next/Prisma) with three
shapes: `websiteJsonLd` + `organizationJsonLd` (both rendered once, in
`app/layout.tsx`, via `<JsonLd>` from `web/components/JsonLd.tsx`), and
`breadcrumbJsonLd` (rendered per-page on `/profile/[id]`, `/divisions/[id]`, and
`/seasons/[id]`). The Organization's `logo` is the shared OG card
(`public/og-image.png`); its `sameAs` is the admin-configured Discord invite URL
(`LeagueConfig` key `discord_server_invite_url`) when one is set, omitted
otherwise. `Event`/`SportsEvent` and `FAQPage` markup are deliberately not built --
Google doesn't show rich results for either here (virtual-only events; FAQ rich
results have been government/health-only since 2023).

## The default OG image

`public/og-image.png` (1200x630, Card Table felt/gold) is generated by
`web/scripts/generate-og-image.mjs` (sharp rasterizing an SVG). Re-run it from
`web/` after any Card Table palette change in `design-system/MASTER.md`:

```
node scripts/generate-og-image.mjs
```

It's a one-shot build step, not part of `next build` -- the PNG is committed, not
regenerated at deploy time.
